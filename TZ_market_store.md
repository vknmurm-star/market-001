# ТЗ для Claude Code: интернет-магазин «Маркет» (демо-проект для кейса на Kwork)

## Цель проекта

Реальный работающий интернет-магазин с демо-каталогом товаров (косметика/красота), развёрнутый на собственном VDS. Проект нужен как портфолио-кейс для размещения на Kwork — должен выглядеть и работать как настоящий магазин, а не макет.

Один владелец, без мультивендорности: товары и заказы администрирует только владелец сайта, доставку и склад не автоматизируем (в демо-режиме форма заказа сохраняет заявку, реальную интеграцию со службами доставки не подключаем).

## Инфраструктура (по аналогии с site-001 / beauty.an51.su)

- Тот же VDS: kvm.an51.su, Debian, root доступ уже есть
- Субдомен: **market.an51.su** (создать A-запись в Timeweb DNS, как для beauty.an51.su)
- Next.js 16 (App Router), PM2, nginx reverse proxy, HTTPS через certbot на 443
- Отдельный GitHub-репозиторий (например, market-store), автодеплой через cron по тому же паттерну, что в site-001 (deploy.sh с flock-защитой, автопроверка каждые 2 минуты)
- **Использовать существующий skill vds-nextjs-deploy** (C:\Users\User\.claude\skills\vds-nextjs-deploy\SKILL.md) как базовый чеклист разворачивания — там уже описаны все грабли (порт 443, certbot, PM2, автодеплой)

## Стек и хранение данных

- Next.js + Tailwind (для консистентности с уже освоенным стеком)
- База данных: PostgreSQL (лучше подходит для товаров/заказов/остатков, чем файловая CMS) либо SQLite, если не хочется поднимать отдельный сервис БД на VDS с 1GB RAM — на демо-объёме товаров (24 позиции) SQLite вполне достаточно и проще в обслуживании
- Демо-каталог товаров: см. приложенный файл `demo-products.json` — готовые 24 товара в 6 категориях (уход за лицом, уход за телом, волосы, макияж, парфюмерия, аксессуары), с ценами, описаниями и остатками. Использовать как seed-скрипт для наполнения БД при первом запуске.
- Изображения товаров: для демо использовать сгенерированные изображения (Gemini, как для статей site-001) или качественные бесплатные стоковые фото по каждой категории — без использования логотипов и фото реальных брендов, чтобы не было проблем с авторскими правами в публичном кейсе

## Функционал (MVP для кейса)

1. **Каталог**
   - Список товаров по категориям, фильтр по цене
   - Поиск по названию
   - Сортировка (по цене, по популярности/новизне)

2. **Карточка товара**
   - Фото, название, цена (с учётом old_price — зачёркнутая старая цена, если есть), описание, остаток на складе
   - Кнопка «В корзину»
   - Блок «Похожие товары» (по той же категории)

3. **Корзина**
   - Изменение количества, удаление товара
   - Пересчёт суммы
   - Переход к оформлению заказа

4. **Оформление заказа**
   - Форма: имя, телефон, email, адрес доставки, комментарий
   - Выбор способа оплаты: онлайн (тестовый режим ЮKassa) или «при получении» (для демо оба варианта просто фиксируют заказ)
   - Страница подтверждения заказа с номером

5. **Личный кабинет покупателя**
   - Простая авторизация по email (без соцсетей, чтобы не усложнять)
   - История заказов

6. **Админ-панель** (закрытая, базовая авторизация по логину/паролю, НЕ публичная Decap CMS — для управления товарами с ценами и остатками удобнее собственная простая CRUD-панель)
   - Список товаров, добавление/редактирование/удаление
   - Список заказов, смена статуса (новый / в обработке / выполнен)

7. **Оплата**
   - Интеграция с ЮKassa в тестовом режиме (тестовые ключи, реальные платежи не проводить, это демо-проект) — важно для кейса показать, что приём онлайн-оплаты реализован технически, но явно не проводить настоящие транзакции без реальных реквизитов бизнеса

## Что НЕ делаем в этой версии

- Мультивендорность, кабинеты продавцов, комиссии
- Реальную интеграцию со службами доставки (СДЭК, Boxberry и т.п.) — заглушка «доставка курьером / самовывоз»
- Программы лояльности, промокоды (можно добавить позже как апсейл-функционал для реальных клиентов с Kwork)

## SEO/базовая гигиена (по чеклисту из skill vds-nextjs-deploy)

- Мета-теги, canonical, OG-теги на всех типах страниц
- sitemap.xml, robots.txt
- Alt-тексты у всех изображений товаров
- JSON-LD Product/Offer разметка на карточках товаров (важно для реалистичности кейса — это то, что реальные интернет-магазины обязаны иметь для Google/Яндекс.Маркета)

## Порядок работ

1. Инициализировать репозиторий, настроить Next.js + БД (SQLite) локально
2. Реализовать модели данных: Category, Product, Order, OrderItem, User (упрощённый)
3. Засеять БД товарами из demo-products.json
4. Собрать каталог, карточку товара, корзину (клиентское состояние + БД для заказов)
5. Сделать оформление заказа + тестовую интеграцию ЮKassa
6. Собрать простую админ-панель (товары, заказы)
7. Задеплоить на market.an51.su по существующему skill-чеклисту (DNS, nginx, certbot, PM2, cron автодеплой)
8. Проверить SEO-гигиену, зафиксировать в CLAUDE.md конфигурацию проекта (как сделано в site-001)
